# 翎迹 · 环志重捕证据台

翎迹整理虚构样地网络的环志报文。它按换环凭据生效时刻关联个体，裁决不同来源的复遇记录，从可确认的相邻遭遇生成移动段，并允许复核人员封存、复算和对账。随附数据均为合成样例。

## 本机启动

需要 Python 3.11 或更新版本。后端使用 Python 标准库和 SQLite，前端使用原生 HTML、CSS 和浏览器 ES modules。运行时无需安装依赖。

```sh
python3 -B -m ringtrace --demo
```

浏览器打开 `http://127.0.0.1:8864`。首次启动会在 `var/ringtrace.sqlite3` 创建数据库。`--demo` 仅在空库加载合成样例，重复启动会保留当前资料。可用 `--db /path/to/ringtrace.sqlite3` 独立指定库文件，用 `--port 8865` 指定端口。

## 演练一次晚到报文对账

1. 用 `--demo` 启动空库。工作台显示修订 3。打开移动证据，沿 `RING-A` 查看四段记录与 `E30` 的两条候选报文。换环生效时刻的新环报文可确认，旧环报文留在追溯证据中。
2. 在封存对账页封存修订 3。进入采集包页，选择 `examples/mud-late.json` 做导入试算，查看拟留置的 `E40` 和受影响的移动段，然后确认入库。
3. 查看修订 4 的移动证据。`E40` 的两条最高优先级报文互相矛盾，`E30 → E40` 和 `E40 → E50` 随之消失，工作台留下待复核断点。
4. 封存修订 4 并与修订 3 对账。分别运行复算，下载两版证据 JSON 与移动段 CSV。在采集包详情下载规范归档 JSON，在追溯索引按 `E40` 查看来源。

## 演练换环失证与补报恢复的中途缺席

合成资料另含一只白沙洲个体的换环过程（环根 `RING-D`，新环 `RING-E`）：

1. 依次导入 `examples/shoal-early.json`、`examples/field-may.json`，封存当前修订。移动证据里 `G10 → G20 → G30` 三段同在。
2. 登记 `examples/reband-may.json`（修订推进，换环生效）。旧环 `RING-D` 的 `G30` 报文在换环时刻后失效，`G30` 留置，`G20 → G30` 从工作台消失。
3. 导入 `examples/shoal-mid.json`。这是另一只鸟的无关入账，修订推进但缺席不被拆开。
4. 沙脊站补报 `examples/shoal-late.json`：同一只鸟以新环 `RING-E` 复遇 `G30`，移动段恢复。封存该修订。
5. 在封存对账页对首尾两版选择「查中途缺席」。界面列出共有移动段、逐版在案情况，以及缺席段的首次失证修订、连续缺席最后一版、恢复修订和导致失证的换环凭据、导致恢复的采集包。
6. 在缺席详情里对每个缺席修订点「正式补封」。补封只按该修订当时已入账的资料重建，不推进工作修订；重复补封回放同一份封存。用原入口下载该版证据 JSON 和移动段 CSV 并独立复算。补封前后、即使之后再收新包，缺席统计始终是同一段。

## 构建与工作流校验

构建检查另需 Node.js 18 或更新版本，用于解析浏览器模块。

```sh
python3 -B -m tools.build
python3 -B -m tools.smoke
python3 -B -m tools.smoke --http
```

演练使用临时数据库，`--http` 另外在系统分配的本机端口验证同一组入口。`--through <阶段>` 运行到指定阶段，可用 `--help` 查看阶段名。

- `ringtrace/` 包含 HTTP 适配、批次接收、SQLite 持久化、谱系、裁决、汇总和封存。
- `web/` 包含工作台、六个页面模块、共享展示和请求层。
- `examples/` 包含合成采集包和换环凭据。
- `tools/` 包含构建检查和工作流演练。

交付形态为本机单库工作台。产品规则与 HTTP 入口见 [PROJECT_SPEC.md](PROJECT_SPEC.md)。
